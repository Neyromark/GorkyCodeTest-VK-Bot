# GorkyCodeTest-VK-Bot

Входная точка умного календаря во ВКонтакте. Бот работает через Long Poll
сообщества, принимает текстовые и голосовые сообщения, пересылает текст на
бэкенд и одновременно поднимает HTTP-сервер, через который бэкенд и сервис
напоминаний присылают ответы пользователю.

Стек: Python 3.12, [vkbottle](https://github.com/vkbottle/vkbottle) 4.x,
FastAPI, Vosk (распознавание речи), Silero TTS (синтез речи),
pydub + ffmpeg (конвертация аудио).
HTTP-сервер слушает порт `80` — на нём же VK-бот доступен внутри сети
`app-network` как `http://vkbottle_bot`.

## Запуск

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU-сборка, как в Docker
pip install -r requirements.txt     # Python 3.12, нужен установленный ffmpeg
cp .env.example .env                # впишите VK_TOKEN
python main.py
```

Кто работает через `uv`: в `pyproject.toml` настроен CPU-индекс PyTorch,
достаточно `uv sync`. Обычный `pip install -r requirements.txt` без первого
шага поставит полный torch с CUDA — он лишний и тянет несколько гигабайт.

Из корня репозитория:

```bash
docker network create app-network 2>/dev/null || true   # сеть объявлена как external
docker compose up -d --build vkbottle_bot
```

В контейнере уже установлен `ffmpeg`, модель Vosk скачивается при первом старте
в том `vosk_models` (`/root/.cache/vosk`), поэтому пересоздание контейнера не
вызывает повторную загрузку. Первый запуск требует доступа в интернет.
Модель Silero TTS, наоборот, запекается **на этапе сборки образа** скриптом
`scripts/bake_tts_model.py` (свои повторы и таймауты на сокет: у `torch.hub` в
сборке закачка виснет). Если не вышло — бот догрузит её при старте, загрузка
не роняет процесс.

## Переменные окружения

В Docker переменные подставляет `env_file: .env` из `docker-compose.yml`
(файл обязателен), при локальном запуске их нужно экспортировать самому.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VK_TOKEN` | — (обязательна) | Токен сообщества ВК с доступом к сообщениям; без него бот падает на импорте |
| `HOST` | `localhost` | Хост бэкенда, куда пересылаются сообщения |
| `PORT` | `8000` | Порт бэкенда |
| `TTS_SPEAKER` | `baya` | Голос озвучки: `aidar`, `baya`, `kseniya`, `xenia`, `eugene` |
| `TTS_MODEL` | `v5_6_ru` | Русская модель Silero; другая скачается при первом голосовом ответе |

В Docker: `HOST=backend`, `PORT=8000`. Значения из `.env.example`
(`localhost`) годятся только для локального запуска.

## Обработка сообщений

| Событие | Обработчик | Поведение |
| --- | --- | --- |
| Личное сообщение «начать» | `handlers/menu.py` | Отвечает «Привет» |
| Любой текст | `text_handler` | Пересылает текст в бэкенд, при недоступности — «❌ Сервер недоступен…» |
| Голосовое (`audio_message`) | `voice_handler` | Скачивает файл, распознаёт и пересылает текст в бэкенд |

`voice_handler`:

1. берёт `link_ogg` (или `link_mp3`) из вложения;
2. скачивает файл через HTTP-клиент vkbottle в память, с браузерным `User-Agent`
   и `Referer: https://vk.com/` (ВК иначе может вернуть страницу ошибки);
3. конвертирует в WAV 16 кГц, моно, 16 бит (pydub/ffmpeg);
4. распознаёт моделью `vosk-model-small-ru-0.22` в отдельном потоке
   (`asyncio.to_thread`), не более двух распознаваний одновременно
   (`MAX_CONCURRENT_TRANSCRIPTIONS = 2`);
5. удаляет служебное сообщение «Скачиваю…» и отправляет распознанный текст в
   бэкенд.

Сам бот ответ на сообщение не формирует: текст ответа приходит от бэкенда через
`POST /api/v1/send-message`.

## Озвучка ответов (TTS)

Если пользователь написал **голосовым сообщением**, ответ бота дублируется
голосовым: текст уходит как обычно, озвучка идёт **фоновой задачей** после
него — HTTP-ответ бэкенду не ждёт синтеза (`src/api/listener.py:send_voice_reply`).
Текстовые собеседники получают только текст — режим хранится в
`src/funcs/voice_mode.py` (в памяти процесса, как и дедупликация запросов).

Как это работает:

1. `src/funcs/tts.py` синтезирует текст моделью **Silero TTS** (`v5_6_ru`,
   голос из `TTS_SPEAKER`) на CPU: до двух синтезов одновременно, всё в
   отдельном потоке через `asyncio.to_thread`.
2. Перед озвучкой из текста убираются эмодзи и знаки (✅, ⚠️, 💼) — модель
   их не читает; длинный ответ обрезается по границе предложения (лимит
   голосового сообщения ВК — 5 минут).
3. WAV конвертируется pydub/ffmpeg в **Ogg Opus 16 кГц моно 16 kbit/s** —
   формат, который ВК показывает как голосовое сообщение.
4. Файл загружается через `VoiceUploader` (наследник `vkbottle.VoiceMessageUploader`,
   `docs.getMessagesUploadServer` → `docs.save`) и отправляется вложением
   отдельным `messages.send`. Сервер загрузки ВК периодически отвечает
   HTML-страницей 504 вместо JSON — тогда загрузка повторяется до 4 раз с
   растущей паузой (2/10/30 сек), каждый раз по свежему URL загрузки;
   `random_id` одинаковый во всех попытках, дубликата не будет.

Ошибка синтеза или загрузки не ломает доставку: текст уже отправлен, поэтому
синтез выполняется в фоне и ограничен таймаутом-страховкой (180 сек),
а любая ошибка просто пишется в лог — в том числе статус и начало ответа
сервера загрузки, если разобрать его не удалось (без этого в логе оставался
только `JSONDecodeError: Expecting value`). Синтез не в HTTP-запросе —
иначе ответ бэкенду задерживался бы на десятки секунд, у бэкенда
срабатывал его таймаут (10 сек), и голосовое под нагрузкой не укладывалось
в лимит запроса.
Модель (~140 МБ) скачивается на этапе сборки образа; если не вышло — бот
догрузит её при старте, и эта загрузка тоже ограничена по времени (180 сек),
чтобы бот не завис в ожидании обрыва связи. Если и тогда не вышло, бот
запускается без озвучки, а модель достроится при следующей попытке.

## API

### `POST /api/v1/send-message`

Отправляет сообщение пользователю ВК.

```http
POST /api/v1/send-message
Content-Type: application/json
X-Request-ID: 6f1c1f9a-6a58-4a3e-9a8e-9d3e0b0f7c11   # обязателен, UUID4

{"type": "message", "user_id": 123456, "message": "Задача сохранена"}
```

```json
{"query_id": "6f1c1f9a-...", "status": "done", "result": {"sent": true}}
```

* `type` — только `message` (проверяется регулярным выражением);
* `400` — нет заголовка `X-Request-ID` или это не UUID4;
* `500` — ВК не принял сообщение; запрос при этом освобождается, чтобы его можно
  было повторить;
* `status: "already_done"` — этот `X-Request-ID` уже обработан;
* для пользователя в голосовом режиме после текста уходит голосовое
  сообщение с тем же ответом (см. «Озвучка ответов»).

Идемпотентность — `InMemoryIdempotency` (`src/api/idempotency.py`): хранит
обработанные UUID 24 часа под `asyncio.Lock`. Дополнительно в ВК передаётся
`random_id`, полученный из первых 4 байт UUID, — защита от дублей на стороне ВК.

## Структура

```
main.py                 загрузка хэндлеров, моделей Vosk и Silero TTS, longpoll + uvicorn
scripts/
└── bake_tts_model.py   запекание модели Silero в образ при сборке
src/
├── bot.py              Bot, API и labeler (vbml_ignore_case)
├── api/
│   ├── listener.py     FastAPI-приложение и POST /api/v1/send-message
│   └── idempotency.py  in-memory дедупликация запросов
├── funcs/
│   ├── sender.py       POST /api/v1/get-message в бэкенд
│   ├── stt.py          Vosk: конвертация и распознавание аудио
│   ├── tts.py          Silero TTS: синтез голосового сообщения ВК
│   └── voice_mode.py   кто пишет голосом (ответы таким — голосовые)
└── handlers/
    └── menu.py         текстовые, голосовые сообщения и команда «начать»
```

Docker-образ ставит `ffmpeg`, монтирует каталог модуля в `/app` и том с кэшем
моделей, публикует порт `80` (контейнер `vkbottle_bot`) и подключает общую сеть
`app-network`.

## Замечания

* Порт `80` на хосте требует прав: локальный запуск без root/Docker возможен
  только после изменения порта в `main.py`.
* Дедупликация в памяти: при нескольких экземплярах нужен общий стор, а
  перезапуск очищает историю запросов.
* Голосовые длиннее разумного и шумные записи распознаются плохо — модель
  маленькая, только русский язык.
* Озвучка тоже грузит CPU: синтез занимает доли секунды на короткий ответ,
  поэтому одновременных синтезов не больше двух. Лицензия моделей Silero —
  CC BY-NC, то есть для некоммерческого проекта.
* Тестов в модуле нет; проверка — реальный диалог с сообществом.
